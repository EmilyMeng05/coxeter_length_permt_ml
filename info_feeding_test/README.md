# Project Summary

For this project, we train a Transformer model to learn multiple mathematical representations of the same object: a permutation. The goal is to predict the Coxeter length of a permutation by providing the model with different combinations of its mathematical encodings.

Instead of treating the input as numerical features, we represent mathematical objects as a sequence of tokens, similar to how a language model processes text. Each permutation is converted into a mathematical sentence, where different representations act as different descriptions of the same underlying object.

The four different representations for permutation `[3 1 4 2]` are:

1. One line notation

```
[3 1 4 2]
```

2. Cycle notation

```
(1 3 4 2)
```

3. Lehmer code

```
[2 0 1 0]
```

4. Inversion vector

```
[2 0 1 0]
```

The model learns the relationship between these representations and the Coxeter length.

# Research Idea

A permutation can be represented in many mathematically equivalent ways. Different representations expose different structural properties of the permutation.

The goal of this project is to investigate:

* Which mathematical representations are most informative for a Transformer?
* Does combining multiple representations improve prediction performance?
* Are some representations redundant?
* Can a Transformer learn algebraic structures from a mathematical language representation?

# Mathematical Language Representation

Each input is converted into a token sequence.

For example:

```
<BOS>
<TASK>
<LENGTH>

<ONE>
3 1 4 2

<CYCLE>
( 1 3 4 2 )

<LEHMER>
2 0 1 0

<INV>
2 0 1 0

<EOS>
```

The target sequence is generated autoregressively:

```
<BOS>
3
<EOS>
```

where `3` is the Coxeter length.

The tokenizer defines the mathematical vocabulary, including:

* Special tokens
* Representation markers
* Numbers
* Cycle notation symbols

# Dataset Generation

The dataset is generated by enumerating permutations and computing multiple representations.

Each row contains:

| Column           | Description         |
| ---------------- | ------------------- |
| id               | Unique identifier   |
| n                | Size of permutation |
| one_line         | One-line notation   |
| cycle            | Cycle notation      |
| lehmer           | Lehmer code         |
| inversion_vector | Inversion vector    |
| coxeter_length   | Target value        |

The dataset is split into:

* Training set
* Validation set
* Test set

# Model Architecture

The model uses a decoder Transformer with autoregressive generation.

The architecture follows the language modeling framework:

Input:

```
Mathematical representation tokens
```

↓

Transformer Decoder

↓

Output:

```
Coxeter length tokens
```

During training, teacher forcing is used:

Input:

```
<BOS>
```

The model learns to predict:

```
Coxeter length
<EOS>
```

The loss function is Cross Entropy Loss over the output vocabulary.

# Training

The model is trained using:

* Optimizer: Adam
* Learning rate: 1e-4
* Loss function: Cross Entropy Loss
* Batch size: 32

Training and validation losses are recorded for every epoch.

The trained model and training history are saved after training.

# Ablation Study

To understand the contribution of each mathematical representation, we perform a complete combinatorial ablation study.

The four representations are:

* One line notation
* Cycle notation
* Lehmer code
* Inversion vector

All possible combinations are tested:

* E1: One representation
* E2: Two representations
* E3: Three representations
* E4: All four representations

A total of:

```
2^4 - 1 = 15
```

experiments are performed.

Each experiment uses:

* The same Transformer architecture
* The same optimizer
* The same training procedure

Only the input representation changes.

# Evaluation Metrics

The model is evaluated using:

## Test Loss

The final cross entropy loss on unseen test data.

Lower values indicate better optimization performance.

## Token Accuracy

The percentage of correctly predicted output tokens.

## Exact Accuracy

The percentage of examples where the entire predicted sequence exactly matches the target sequence.

For this task, since the target is a single integer, exact accuracy measures whether the model predicts the Coxeter length correctly.

# Results

The ablation study shows that different mathematical representations provide different amounts of information.

The strongest individual representations are:

* Lehmer code
* Inversion vector

These representations achieve higher accuracy compared to one-line notation and cycle notation.

The best-performing combinations include:

```
Lehmer + Inversion Vector
```

and

```
One-line + Cycle + Lehmer + Inversion Vector
```

The full multi-encoding model achieves the lowest test loss, suggesting that combining multiple mathematical views allows the Transformer to better learn the underlying permutation structure.
